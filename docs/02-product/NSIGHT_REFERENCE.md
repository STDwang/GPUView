# Nsight Systems参考与GPUView v0.4范围

日期：2026-09-25。依据用户“参考NVIDIA Nsight Systems继续完善”的要求实现本轮功能。

参考[NVIDIA Nsight Systems官方用户指南](https://docs.nvidia.com/nsight-systems/UserGuide/)的Events View、Timeline/Events Correlation与Function table：事件表可以搜索/排序，并与时间轴定位联动。GPUView借鉴该分析流程，UI和代码独立实现，不复制品牌界面，也不声称能读取.nsys-rep或具备CUDA采集能力。

## 本轮已实现

| 工作流 | GPUView行为 |
|---|---|
| 在事件表查找 | 名称字面子串、完整时长上下限，输入180ms防抖 |
| 查看选区数据 | 默认“仅选区”，无框选时使用全会话；取消勾选则搜索全会话 |
| 查看当前轨道 | 遵循轨道过滤/勾选/折叠；帧模式进一步限制为统计页当前组 |
| 表格到时间轴 | 单击高亮、双击定位，上一条/下一条按当前排序循环定位 |
| 时间轴到表格 | 按稳定ID选中当前搜索结果；不匹配时不误选其他行 |
| 看主要耗时名称 | 次数、贡献总和、平均贡献、最大贡献；双击定位贡献最大的事件 |
| 避免旧结果覆盖 | 一运行+一最新待办，参数改变立即失效旧结果，支持取消和退出等待 |

本面板显示全部匹配事件，不静默限制到前10000条。达到Qt表格int行数上限时显式报错；百万行使用Model/View按需取值。

## 明确的语义和边界

- 名称区分大小写，按UTF-8字面子串匹配，无正则或模糊匹配。
- 时长下限/上限都是原始完整时长，含边界；上限0表示不限。下限大于上限报错。
- Trace按区间相交入选，范围贡献为选区内交集；帧按Present时刻属于[begin,end)入选，范围贡献为完整帧间隔。
- 名称汇总合并同名事件及当前所选轨道；贡献总和是事件时长求和，并发可超过墙钟，不能称为GPU利用率、调用栈占比或关键路径。
- 名称汇总双击定位贡献最大项；相同贡献用较小稳定ID确定代表事件。
- 单纯缩放不修改框选条件，与Nsight某些基于当前zoom筛选的视图不同，避免双击定位后把搜索结果缩成单条。
- 事件分析的名称/时长条件只影响本面板。v0.3帧导出仍取统计页组和选区，不包含本面板条件；本轮未提供搜索结果导出。
- 仍使用教学Trace及PresentMon v1帧数据。真实Kernel/API关联、调用栈、系统采样、遥测、Trace文件导入和回放另列后续任务。

## 演示步骤

1. 生成10万教学事件，在底部“事件分析 / 名称汇总”输入Kernel，得到两个教学名称的匹配事件。
2. 点完整时长表头降序，单击高亮，双击定位；上一条/下一条在当前排序中循环。
3. 框选范围，比较完整时长与范围贡献；切换“按名称汇总”查看次数和贡献总和，双击最大项。
4. 快速修改名称或时长，再取消，确认过期结果不会重新出现。
5. 导入公开帧CSV，对比Present归属与Trace相交规则；从底部另一标签进入原有帧导出。
