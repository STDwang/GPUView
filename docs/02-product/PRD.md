# GPUView 产品需求文档

版本：v1.0｜状态：范围已确认，功能分阶段实施｜主要用户：项目作者、面试官、桌面性能分析学习者

## 1. 目标与成功条件

学习与面试补充要求：模块解耦、关键中文注释、公开GPUView仓库、持续维护README。每个关键功能关联指定面试题、实际问题、解决取舍、代码例子和验证证据。用户理解和讲解能力是学习目标，不要求所有代码亲手编写。

用户能够从一份性能数据中定位异常时间范围，查看相关指标，导出可复核摘要，并解释工具自身如何在大量数据下保持交互响应。

第一阶段最终成功条件：可离线运行的 Widgets 程序；一份真实帧数据分析；一份明确标注的多轨 Trace 演示；百万事件基准及至少一次优化前后对照；作者能解释数据来源、指标口径、线程边界、LOD 和缺失数据处理。完整第一阶段为 A+B。

不在第一阶段范围：自研驱动、GPU 指令级采样、直接解析 Nsight 私有报告、ETL 原生解析、游戏注入/Overlay、云端账号、在线 AI 诊断、完整数据库服务、完整 Nsight 复刻。AI 是开发协作方式，不是产品必须联网的功能。

## 2. 核心使用流程

打开文件 → 校验格式与字段 → 选择进程/交换链 → 查看总览 → 在曲线/热力图定位长帧 → 框选区间 → 查看统计及原始字段 → 导出摘要。

B 增加：关联同一会话遥测 → 显示对齐质量 → 联动查看资源；导入 Trace → 查看多轨区间及重叠 → 按名称聚合；回放固定数据 → 暂停/恢复 → 查看工具刷新与积压指标。

## 3. 功能需求

P0-A 为最小闭环必需；P0-B 为完整 Widgets 版必需；P1 为可选扩展。

| ID | 优先级 | 功能与行为 | 可检查的完成条件 |
|---|---|---|---|
| FR-01 | P0-A | CSV 文件选择/拖放；识别登记过的 PresentMon 表头；预览来源、字段、单位 | 支持一个实际验证的本机版本；未知表头明确报错，不按列号猜测 |
| FR-02 | P0-A | 后台分块读取、进度、取消；成功后发布新会话 | 载入中可操作窗口；取消/失败保留旧会话；不显示新旧混合数据 |
| FR-03 | P0-A | 单进程、单交换链分析，可切换 | 切换后统计与视图同步；默认选择规则可见，不将多个交换链混成 FPS |
| FR-04 | P0-A | 自绘帧时间曲线、缩放、平移、悬停、框选和全局概览 | 可定位具体帧 ID；视口缩放不改变选区统计；数据尖峰不被降采样抹掉 |
| FR-05 | P0-A | 总帧数、有效样本数、平均 FPS、P50/P95/P99、长帧数 | 口径见 DATA_SPEC；无有效样本显示 N/A；提供单位和统计范围 |
| FR-06 | P0-A | 帧时间热力图，固定时间桶，显示桶内最大帧时 | 点击桶定位选区；空桶显示缺失；色标与当前单位可见 |
| FR-07 | P0-A | 明细表、搜索、过滤、排序与事件详情 | 通过稳定 ID 联动；排序后选中项不指错帧；详情保留原始字段 |
| FR-08 | P0-A | 选区联动统计/详情；筛选状态可见可清空 | 所有面板使用同一范围和过滤版本；旧异步结果不得覆盖新选区 |
| FR-09 | P0-A | 导出 UTF-8 CSV 摘要和 Markdown 分析报告 | 包含源文件哈希、版本、筛选、指标口径、缺失计数及用户备注；不上传 |
| FR-10 | P0-A | 错误/警告面板与空状态 | 错误显示文件、行号或阶段、原因、可采取操作；损坏行不得静默消失 |
| FR-11 | P0-B | NVIDIA 遥测导入及资源曲线 | 至少验证 GPU 利用率与显存两字段；其他指标按能力显示；标明整卡范围 |
| FR-12 | P0-B | 多源时间关联 | 只自动关联有共同时间依据的会话；未知偏移显式标注，禁止自动因果结论 |
| FR-13 | P0-B | 多轨 Trace 子集，支持完整区间 X、数值计数器 C、命名元数据 M 的约定子集 | CPU/Stream/Kernel/拷贝轨道可折叠、拾取；不支持的事件统计并报告 |
| FR-14 | P0-B | Trace 按名称、类别、轨道聚合 count/sum/mean/P95 | 使用原始事件计算；总耗时不等于 GPU 墙钟占用率；明确重叠事件语义 |
| FR-15 | P0-B | 离线受控回放，1x/2x/暂停/重置，UI 最高20Hz数据发布 | 窗口/内存有界；暂停停在固定游标；界面常显“回放”；不称为实时采集 |
| FR-16 | P0-B | 自身性能诊断面板 | 显示查询/绘制耗时、可见事件量、聚合数量、待处理请求；可导出测量 |
| FR-17 | P0-B | 百万事件可视化与打包 | 按 ACCEPTANCE 记录数据规模、首屏/加载/内存/交互；包在无开发SDK环境验证 |
| FR-18 | P1 | A/B 两次采集对比 | 仅同场景、同口径时输出变化；不能混用不同工具版本字段定义 |
| FR-19 | P1 | 调用树/栈、真实 CUDA Trace、实时采集控制 | 必须先补数据协议和验收用例；单独评审增量范围 |

## 4. 非功能需求

- 默认中文界面，指标保留标准英文缩写及提示；适配 1280×720 及以上、100%/150%/200% 缩放。
- 所有计算基于原始有效记录。渲染降采样不影响统计结果。
- 数值精度、时间范围、缺失比例和模拟来源可追溯；没有字段不补零、不伪造。
- 导入、索引与长时间统计不得在 GUI 线程运行；高频更新有合并和积压上限。
- 性能目标与测试方法统一见 ACCEPTANCE，文档中的数字均是候选门槛。
- 离线打开已有数据无需管理员权限；采集工具权限需求单独处理。
- 大文件导入超过候选预算时中止并解释，不让系统耗尽内存。首版非磁盘数据库，不承诺无限大小。

## 5. 产品指标与交付边界

A 验收以 FR-01～FR-10 全通过为准；B 以 FR-11～FR-17 及其测试通过为准。P1 不纳入 A/B 完成条件。没有真实样本时可以继续开发合成测试，但 A 不能宣布完成。

交付包应包含程序、最小演示样本、操作说明、数据来源说明、性能报告、已知限制和第三方组件声明。真实数据公开前移除账号、路径等不必要字段；原始文件只留本地。

## 6. 变更管理

需求使用 FR 编号追踪。用户确认后锁定 v1.0 基线；增加数据格式、实时采集、数据库或新平台需说明成本并更新版本。指标口径变更必须同步 DATA_SPEC、fixtures、测试和导出版本号。
