# 任务包、学习与协作路线

版本：v1.0｜按任务推进，不设固定周数；以理解、复现和讲解为验收，不要求全量亲手编码

用户最新节奏：每周时间不定，有额度时使用。旧计划的每周12–14小时不再作为约束。一个任务只推进一个可验收目标；额度快用完时保存停点，不通过减少验收来“完成”。本文不创建自动化、不预定未来运行。

## 1. 任务依赖

执行调整：为让用户提供的十个问题尽早对应真实代码，先交付规模/线程教学内核（覆盖T02/T05/T11部分内容）。这不代表跳过T01真实CSV核验或A的业务功能；后续回到真实帧数据闭环。Quick同样允许AI辅助，按理解/复现/讲解验收。

G0文档确认 → T01环境/数据验证 → T02数据契约 → T03导入 → T04统计 → T05时间线 → T06联动/热力图 → T07真实闭环与导出（A） → T08遥测 → T09 Trace → T10回放 → T11性能优化 → T12打包与面试（B） → Q阶段（C）。

T08/T09可按资料可用性调整顺序，T11的性能记录从T05起就开始，不等所有功能做完才测量。

| 任务 | 开发成果 | 当次学习主题 | 学习验收 |
|---|---|---|---|
| T01 | 独立Qt6 Kit、构建/测试最小检查、实际CSV样本及manifest | CPU/GPU、帧提交与执行、进程、采样 | 画一条“CPU准备→提交→GPU执行→显示”的流程并指出可能重叠处 |
| T02 | 数据类型、单位转换、手算fixtures | 时间基准、缺失值、测量与推断 | 用4条数据独立算均值/P95/FPS |
| T03 | 后台CSV导入、取消、错误、旧会话保留 | QObject归属、队列连接、所有权 | 说明为什么worker不能改界面，修改一个取消检查点并验证 |
| T04 | 筛选、分组、精确统计 | 平均FPS与分位数、交换链 | 解释为何不能平均瞬时FPS，增加边界用例 |
| T05 | 时间线、坐标映射、缩放/平移、命中 | QPainter、时间投影、视口查询 | 独立实现或重写“以鼠标为锚点缩放”小函数 |
| T06 | 热力图、明细表、联动状态 | Model/View、稳定ID、状态一致性 | 定位一次排序后选择错误，解释修复 |
| T07 | 真实样本完整分析、导出、A包 | 数据质量、复现、分析边界 | 用自己的话讲清一次长帧以及不能据此确认的原因 |
| T08 | 遥测曲线、对齐质量显示 | 单调/墙钟、低频采样、整卡指标 | 解释200ms样本为何无法定位16ms内的变化 |
| T09 | X/C/M子集、多轨、名称聚合 | Kernel/Stream/Memcpy、并发、区间并集 | 用教学数据算重叠区间总时长与墙钟占用的区别 |
| T10 | 受控回放、合并刷新、队列上限 | 生产/消费、背压、快照 | 改变回放速率，证明不会积累无界UI事件 |
| T11 | 100k/1m基准、优化前后报告 | LOD、缓存失效、剖析、内存布局 | 提出一个可测假设，自己运行对照并解释收益/代价 |
| T12 | 干净环境包、录像、架构复盘 | 工程交付、技术陈述 | 10分钟讲解+10分钟追问，能指出至少3个限制 |

若额度只够小段工作，将任务拆成“一个算法+测试”“一个交互+验证”“一份基准+结论”。依赖未完成时不开始大面积UI代码生成。已通过的检查不无故反复运行。

## 2. 每个任务的固定节奏

1. 先解释本次问题及需要的2～3个概念，示例尽量使用项目真实数据。
2. 说明接口、输入输出、失败状态和验收方式。
3. AI完成约定实现、测试与必要文档更新，展示一个最小可观察结果。
4. 用户进行一次独立计算、局部修改或口述；记录“能解释/需提示/未练习”。
5. 保存完成项、已执行检查、未解决问题和下一次入口。

用户可选择先让AI跑通一个完整任务，再学习；不强制每段代码前提问打断。第一轮AI可以写全部产品代码，但“运行通过”和“用户已掌握”必须分开记录。

## 3. 学习材料模板

每个learning主题保留：遇到的问题 → 最小概念解释 → 项目中的真实位置 → 可运行/可手算练习 → 常见误解 → 面试口述 → 自评。无需先读完整体系结构教材。

重点误解清单：CPU提交不等于GPU完成；GPU Busy不等于SM利用率；显存占用不等于带宽；FPS均值不代表流畅性；异步不代表无限创建线程；20HzUI不代表20Hz采样；降采样不应改变统计；曲线相关不证明因果；名称聚合不等于调用栈。

## 4. 上下文与文件管理

每次结束更新docs/00-review/STATUS.md：任务ID、完成到哪、改动文件、运行命令与结果、未解决风险、用户尚未做的练习、下次第一步。重大决策更新架构ADR，需求变化更新PRD。

开发后每个可运行里程碑使用明确Git提交；未跑通的工作保留说明，不用误导性“完成”提交消息。命令、路径和构建依赖写入文档，不依赖聊天记录才能启动项目。额度剩余未知时不猜测，也不主动消费额外付费额度。

## 5. 完整第一阶段的学习关卡

你应能不看AI答复解释：一帧数据从文件到屏幕经过哪些模块；一次范围选择怎样避免旧结果覆盖；为什么百万事件不需要百万个控件；长事件为什么不能只按开始时间查；如何证明性能变化；当前工具在哪些方面不能判断GPU瓶颈。答不清的项回到对应小任务，而不是继续堆功能。
