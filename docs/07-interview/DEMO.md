# 面试演示与证据清单

版本：v0.1｜计划稿，任何业绩数字需完成后实测填写

## 5分钟演示

| 时间 | 动作 | 传达的能力 |
|---|---|---|
| 0:00～0:30 | 说明这是Qt可视化工具，展示数据来源及版本 | 需求理解与业务边界 |
| 0:30～1:30 | 打开真实帧数据，定位长帧、框选、查看统计 | 自定义交互、业务语义、Model/View |
| 1:30～2:15 | 查看相关遥测，说明整卡/低频/对齐误差 | 对测量限制的理解 |
| 2:15～3:15 | 切换明确标注的教学Trace，多轨缩放、名称聚合 | 区间渲染、轨道、LOD和架构复用 |
| 3:15～4:15 | 百万事件交互、后台取消、性能对照报告 | 线程安全、规模、可复现实测 |
| 4:15～5:00 | 一张架构图，解释一次优化取舍和Quick重做计划 | 设计能力与学习成果 |

A尚未进入B时只演示真实帧闭环，不展示未完成的遥测/Trace/百万事件承诺。视频只是现场环境故障的备份，离线数据应能现场交互。

## 随包证据

真实脱敏样本与manifest、教学Trace生成参数、源代码版本、构建说明、测试结果、基准原始数据、优化报告、已知限制、3～5分钟录像。截图与视频放artifacts/demo，报告放benchmarks/reports。

## 面试追问准备

1. 为什么使用自绘控件，在哪里使用标准View？
2. 如何查询跨越视口但起点在视口外的长事件？
3. 为什么降采样不应改变P99？
4. 新选区发出后旧统计才返回，你怎样防止错位？
5. 取消、异常和关闭窗口时谁拥有worker和数据？
6. GPU Busy、GPU利用率、显存占用各自能说明什么？
7. 1% Low与P99倒数为什么不是同一口径？
8. PresentMon数据为何不能提供调用栈与Kernel细节？
9. 一百万事件下CPU、内存和交互分别测了什么？
10. Quick重做复用了什么，哪些部分必须重新设计？

## 诚实的项目陈述模板

完成后按真实结果填写：

> 基于C++17/Qt Widgets实现性能数据可视化工具，支持[已验证数据格式]，提供时间线、热力图、区间统计和资源视图；采用[实际实现的索引/LOD/快照机制]，在[明确设备和测试条件]下处理[实际规模]，将[具体指标]从[实测值]改善至[实测值]。项目由AI辅助开发，我独立完成了[可证明的设计/验证/重做工作]。

不可使用尚未证明的“生产级”“完整Profiler”“稳定60FPS”“熟练Nsight”“定位到指令级瓶颈”。教学Trace只能证明可视化和算法，不证明真实GPU采集能力；有AI参与可以坦诚说明，重点在你能否解释和改动。
