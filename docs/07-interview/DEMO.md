# 面试演示与证据清单

版本：v0.2｜当前可运行步骤见下文；未完成能力仍按计划标注

## 当前v0.2的5分钟演示

1. 打开data/samples/presentmon-real.csv，进入来源页，解释真实采集、匿名化和受控负载。
2. 统计页展示905条记录和长帧，双击一条长帧；观察帧曲线、金色选择和详情。解释Present间隔不等于Kernel时长。
3. 框选范围查看准确统计，缩放到选区，再返回上一视图；切换轨道过滤，说明统计口径。
4. 生成100万教学事件，CPU/GPU分组折叠/过滤、名称区滚动和事件区缩放；说明LOD近似与精确分析分离。
5. 展示UI_PERFORMANCE及原始CSV，对着StatisticsController和RenderKey解释迟到结果拒绝、缓存失效与性能测量边界。

遥测、热力图、导出和Quick尚未实现，不在现有演示中假装展示。截图见assets/screenshots，复现和问题讲解见P0_P1_WALKTHROUGH.md。录像、干净环境包与用户口述练习仍待完成。

## 面试追问准备

1. 为什么使用自绘控件，在哪里使用标准View？
2. 如何查询跨越视口但起点在视口外的长事件？
3. 为什么降采样不应改变P99？
4. 新选区发出后旧统计才返回，你怎样防止错位？
5. 取消、异常和关闭窗口时谁拥有worker和数据？
6. GPU Busy、GPU利用率、显存占用各自能说明什么？
7. 1% Low与P99倒数为什么不是同一口径？
8. PresentMon数据为何不能提供调用栈与Kernel细节？
9. 一百万事件下CPU、内存和交互分别测了什么？
10. Quick重做复用了什么，哪些部分必须重新设计？

## 诚实的项目陈述模板

完成后按真实结果填写：

> 基于C++17/Qt Widgets实现性能数据可视化工具，支持[已验证数据格式]，提供时间线、热力图、区间统计和资源视图；采用[实际实现的索引/LOD/快照机制]，在[明确设备和测试条件]下处理[实际规模]，将[具体指标]从[实测值]改善至[实测值]。项目由AI辅助开发，我独立完成了[可证明的设计/验证/重做工作]。

不可使用尚未证明的“生产级”“完整Profiler”“稳定60FPS”“熟练Nsight”“定位到指令级瓶颈”。教学Trace只能证明可视化和算法，不证明真实GPU采集能力；有AI参与可以坦诚说明，重点在你能否解释和改动。

## v0.3加演：完整明细与导出（约3分钟）

1. 导入公开905帧样本，点击底部表格“帧间隔ms”降序排序；单击高亮，双击定位最大92.3161ms帧。解释ID与行号不同。
2. 点击热力图某一秒，观察明细数量与统计范围同步；Home回全览。说明颜色取max，不能据此推出GPU利用率。
3. 输入备注导出Markdown与完整帧CSV；展示来源SHA、选区/长帧口径和905帧记录。说明后台固定快照，取消不破坏旧报告。
4. 打开[案例](FRAME_ANALYSIS_WALKTHROUGH.md)沿模型、worker和QSaveFile讲解；性能问题用[测量证据](../../benchmarks/reports/FRAME_ANALYSIS.md)回答，不口头声称60FPS。
