# 帧排序复用对照

日期：2026-10-01。Windows / MSVC 2022 / Qt 6.8.3 / Release，同一二进制、同一进程。100,000和1,000,000条均为**合成帧**：每16,666,667纳秒一个Present，每60帧一条70ms间隔，其余16.666667ms；不是真实采集或真实Kernel。

[原始40条CSV](../results/frame-sort.csv) · [基准程序](../../tools/frame_benchmark/main.cpp)

每规模、每排序预热一对cold/reuse，正式五对；交替执行先后。cold重新计算范围统计、长帧规则和热力图，reuse使用预先建立的同范围结果；两者均完成行排序和ID映射。计时包含结果分配与必要复制，排除生成源数据、建立初次缓存、校验、析构、GUI排队与绘制。

| 合成帧数 | 降序字段 | cold中位数ms | reuse中位数ms |
|---:|---|---:|---:|
| 100,000 | 帧间隔 | 80.68 | 12.62 |
| 100,000 | 长帧标记 | 83.00 | 13.04 |
| 1,000,000 | 帧间隔 | 847.86 | 145.81 |
| 1,000,000 | 长帧标记 | 800.17 | 142.63 |

收益来自跳过与排序无关的统计和全会话热图重建，尤其是每帧历史基线判断。结果不能外推为实际屏幕FPS或端到端交互P95；五次样本只报告中位数。没有与其他日期/程序的基准混算提速。

每轮计时外比较完整事件ID顺序、长帧标记、ID映射、热力概览及P99，不一致即非零退出。核心测试另覆盖八种列/方向组合、全部摘要字段、稀疏桶、半开范围失效、轨道失效、同版本不同快照、取消和旧结果不变。实际905帧UI测试验证表头排序命中复用，热图改变选区时失效。

内存与取消：新结果分块复制行引用和热力数据，旧结果保持不可变；仍为O(N)额外空间，未测峰值内存。复制每1024项、排序每4096次比较检查取消，分配/释放不能中断。控制器只借用最近发布结果，不积累历史缓存。

复现（按README构建Release，将Qt bin加入当前进程PATH）：

```powershell
./build/Release/gpuview_frame_benchmark.exe --sort benchmarks/results/frame-sort-repro.csv -platform offscreen
```
