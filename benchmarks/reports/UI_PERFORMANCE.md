# UI连续交互与缓存对照

日期：2026-09-18。Intel Core i7-12700H / Windows 11 / MSVC 2022 / Qt 6.8.3 / Release / offscreen。TimelineWidget为1000×600逻辑像素，微软雅黑10pt。数据为seed 42教学模拟，100k与1m分别在独立进程运行。

## 测量方法

每个规模预热1轮、不记录；随后3轮，每轮分别缓存开启/关闭，轮间交换先后顺序。每个配置执行缩放、平移、悬停各120次。缓存关闭是同一代码中主动清空几何缓存的消融对照，其他逻辑不变，不是旧版本程序。

`input_to_cpu_paint_ms` 从同步发送输入/设置视口开始，到同步repaint返回；`paint_ms` 是paintEvent内CPU时间。没有真实屏幕呈现、OS输入队列等待、GPU合成或VSYNC测量，不能据此声称稳定60FPS。悬停包含提示文本处理。平移使用同一视口API连续移动；不包含真实鼠标设备采样。

每个规模有2160条记录；表中每组360个采样，P50/P95使用nearest-rank。加载只做了一次，是生成并建索引的耗时，不是文件导入分位数。峰值内存为该独立进程整个运行期间工作集高水位，不是数据数组净大小。

| 事件数 | 动作 | 缓存关 P50/P95 ms | 缓存开 P50/P95 ms |
|---|---|---|---|
| 100000 | zoom | 6.911 / 8.234 | 7.208 / 9.399 |
| 100000 | pan | 2.206 / 2.832 | 2.146 / 2.653 |
| 100000 | hover | 7.569 / 9.195 | 6.375 / 7.771 |
| 1000000 | zoom | 4.340 / 8.981 | 4.280 / 7.457 |
| 1000000 | pan | 4.562 / 8.044 | 4.029 / 7.153 |
| 1000000 | hover | 4.572 / 8.680 | 3.836 / 6.615 |

- 100000事件：单次生成/建索引 7.372 ms；进程峰值工作集 31.15 MiB。
- 1000000事件：单次生成/建索引 64.899 ms；进程峰值工作集 89.79 MiB。

## 结论与限制

悬停不改变数据/视口/轨道，缓存可避免重复查询与几何构建，本次P95降低。缩放和平移使缓存键变化，本来就不应期待命中；它们的开关差异主要反映运行噪声和次序影响，不能归功于缓存。百万事件某些动作快于10万事件，是查询进入概览路径后图元量不同，不能推断数据量增加会普遍加速。

验证：两个缓存配置逐样本图元数相同；UI回归测试另比较开启/关闭缓存时的输出图像。测试不代表其他机器、DPI、后台负载或实际显示器上的体验。若要对外承诺刷新率，仍需Windows窗口后端持续交互、实际呈现时间和更长运行测量。

## 复现与原始记录

先构建Release，并让Qt离屏插件可访问（build.ps1的测试配置说明见BUILD.md）。从仓库根目录运行：

```powershell
$env:QT_QPA_PLATFORM_PLUGIN_PATH = "$PWD/.tools/Qt/6.8.3/msvc2022_64/plugins/platforms"
./build/Release/gpuview_ui_benchmark.exe benchmarks/results/ui-100k.csv 100000 -platform offscreen
./build/Release/gpuview_ui_benchmark.exe benchmarks/results/ui-1m.csv 1000000 -platform offscreen
```
