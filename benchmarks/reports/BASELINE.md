# 首轮查询基准：教学内核 v0.1

日期：2026-09-17。数据为本项目生成的教学Trace，seed42、64轨道，包含稀疏超长事件。所有结果来自 [baseline.csv](../results/baseline.csv)。

## 环境与方法

Windows x64、i7-12700H、约16GB RAM、Qt6.8.3、MSVC19.31、C++17、Release。程序是独立CPU基准，不调用GPU，不从磁盘加载事件。没有控制电源模式/后台负载，因此结果是本机首轮基线，不是稳定性承诺或第三方可直接比较的评分。

每个数据规模预热1次并测量5次。每轮执行100个宽1ms、均匀分布的查询；先全量扫描，再使用区间索引，两者命中数量必须相同。此固定顺序可能有缓存顺序影响，后续完整基准应交替顺序。渲染批次指定1280逻辑像素、16个可见轨道。

## 结果（5轮中位数）

| 指标 | 100k | 1m |
|---|---:|---:|
| 生成+存储+索引+概览构建 | 7.9446ms | 83.5897ms |
| 100次朴素查询合计 | 6.6379ms | 189.406ms |
| 100次索引查询合计 | 0.9124ms | 2.7329ms |
| 一次全览几何批次构建 | 1.1964ms | 1.6536ms |
| 几何图元数量 | 25,008 | 20,336 |
| 100查询命中总数 | 184 | 1,832 |

百万规模查询约69.3倍差异，仅适用于这组窄范围工作负载。全览时输出大量事件不会获得同等比例收益，因此UI还有输出上限与LOD。100k图元多于1m是因为前者可走精确事件路径，后者更多进入概览模式。

原始CSV中的peak_working_set_bytes是独立基准进程截至当时的累计峰值工作集，最大约77MiB；不是私有内存，也不是完整Qt应用峰值。cache_hit_ms接近时钟/优化器测量分辨率，不据此宣传纳秒级性能。

## 尚未验证

- PRD的完整加载时间、私有内存、输入到绘制P95、真实文件解析。
- 真实窗口屏幕呈现帧率、DPI矩阵、长时间回放、干净环境部署。
- Widgets/Graphics View/Quick三框架横向比较。

界面状态栏的paint时间包括当次绘制路径中的查询，但它是CPU回调耗时，截图上的一次值不能作为P95，也不能推算稳定FPS。

## 复现

先按README编译，再运行：

```powershell
./build/Release/gpuview_benchmark.exe benchmarks/results/repro.csv
```

对比时记录源码版本、环境、seed和样本规模，保留CSV。后续优化应在保持命中集合与精确统计一致的前提下讨论收益。
